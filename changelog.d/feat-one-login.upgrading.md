- Breaking: the skill logs in once, with the matrix-e2ee-cli session (`matrix-e2ee-setup.py`). `matrix-send.py`, `matrix-read.py`, `matrix-edit.py`, `matrix-rooms.py`, `matrix-resolve.py`, `matrix-create-room.py`, `matrix-invite.py` and `matrix-power-level.py` run matrix-e2ee-cli instead of sending HTTP requests with the config's token, so `access_token`, `access_token_file` and `MATRIX_ACCESS_TOKEN` are no longer read by any script. A setup that has only an `access_token` and no E2EE device has to run `matrix-e2ee-setup.py` first; then remove the `access_token` from `config.json` (`matrix-doctor.py` warns while it is there, and names the skill's device when the token is that device's own)
- Breaking: matrix-administration no longer reads `access_token`, `access_token_file` or `MATRIX_ACCESS_TOKEN`. Its token comes from `MATRIX_ADMIN_TOKEN`, `admin_token_file` or `admin_token`, else from the access token of the matrix-e2ee-cli session, which is sent to the homeserver recorded in that session and works only when that account is a server admin. A set admin token still wins, even a dead one. Move a server-admin token kept in `access_token` to `admin_token`
- Breaking: a `matrix-watchd.py` started with matrix-e2ee-cli 0.3.0 answers the new requests (`rooms`, `resolve`, `create-room`, `invite`, `power-level`) with "unknown op", and the commands then stop instead of taking the direct path; that includes every lookup of a short room name. Run `matrix-watchd.py --stop` and `--start` after the upgrade
