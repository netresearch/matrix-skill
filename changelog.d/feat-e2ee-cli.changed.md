- `matrix-send-e2ee.py`, `matrix-read-e2ee.py`, `matrix-edit-e2ee.py`, `matrix-download-e2ee.py`, `matrix-fetch-keys.py`, `matrix-e2ee-verify.py`, `matrix-e2ee-setup.py`, `matrix-key-backup.py`, `matrix-react.py`, `matrix-redact.py`, `matrix-watchd.py` and `matrix-watch.py` are stdlib wrappers that keep their names and the flags matrix-e2ee-cli can serve (the others are refused, see Removed) and run the matching matrix-e2ee-cli command. `--debug` is accepted and ignored. A secret given with `--allow-secret-argument` reaches the CLI in its environment, not on its command line. Output, including `Event ID: …` and the `--json` array of `matrix-read-e2ee.py` (its messages now also carry `decrypted`, `sender_verified` and `room_encrypted`), is the CLI's; a failed `--json` send, edit, react or redact still prints `{"error": …}` on stdout, and react adds the keys it set before the failure as `applied`
- `matrix-doctor.py` checks the matrix-e2ee-cli binary (`--install` downloads it) and the CLI's `session.json` instead of matrix-nio, libolm and `credentials.json`
- `matrix-e2ee-setup.py` with a session in place (also right after the takeover) shows its state instead of logging in again; `--force` replaces a dead or foreign device (`matrix-e2ee-cli login --force`). `matrix-doctor.py` and the references name `--force` where a replacement is meant
- A failed takeover reuses the newest `store.backup-<time>` while the store's files are unchanged, and its error names every backup copy
- A new device is named "Matrix Skill E2EE (Rust)"
- A short room name (`ops`, or `#ops` without the server) is looked up before the CLI runs, in the order the E2EE scripts of version 4 used (alias without server, then a single exact display name, then a single partial match; `matrix-react.py` and `matrix-redact.py` follow it too and no longer refuse an exact name that another room's name contains), and only the room ID reaches matrix-e2ee-cli, whose own lookup takes the display name alone. Several matches or none stop the command, and so does a partial-only match for send, edit, react and redact, which write and therefore need an exact alias or name; room IDs and full aliases are passed on unchanged
- `matrix-key-backup.py --status --import-keys` shows the status and imports nothing, as before
- `matrix-watch.py`, and `matrix-watchd.py --status` and `--stop`, do not take a matrix-nio device over: they do not open the store. `matrix-watch.py` ends with exit code 0 on Ctrl-C while following, as before
- `matrix-e2ee-cli.py migrate-nio` copies the store first, like the automatic takeover (a copy that fails stops it with an error, and a run that created the session is recorded even when it exits non-zero, as `--check-online` can), which now runs under `matrix-skill/takeover.lock` so that commands started together take the device over once
