- The E2EE scripts run [matrix-e2ee-cli](https://github.com/netresearch/matrix-e2ee-cli) instead of matrix-nio. The first E2EE command on a machine that has the matrix-nio store (`~/.local/share/matrix-skill/store`) and no matrix-e2ee-cli session copies that store to an owner-only `store.backup-<time>` beside it, then takes the device over with `migrate-nio`: device id, identity keys, verification and room keys stay. Stop a running `matrix-watchd.py` of the old version first; while it holds the store, the command stops and says so. Afterwards run `matrix-key-backup.py --import-keys` once, delete the old store yourself once the new device works (never with `matrix-e2ee-cli.py logout`, which ends the device on the server), and do not run an older version of the skill on the same machine
- `matrix-e2ee-verify.py --request` and `--listen` ask on the terminal whether the emoji match; without a terminal (an agent) use `matrix-e2ee-cli.py verify --listen --hand-over` and `verify --confirm TOKEN` after the person compared the emoji (`references/e2ee-guide.md`)
- `matrix-watch.py` follows the logs of the new daemon, so restart `matrix-watchd.py` after the upgrade; its ROOM is a room ID or the alias or name as written in `watch_rooms`
